# Clean-room note (NASA Space Apps 2026 compliance)

The official 2026 NASA Space Apps Challenge runs **November 14–15, 2026**. Official
guidance allows participants to prepare, learn tools, and explore data beforehand, but
says teams **may not develop the solution they intend to submit before the event
begins**; submitted project work must occur during the event window.

## What this repository is

A **public research/production project** that implements the Planetary Analog OS
morphology-transfer nucleus. It is intended as open-source prior art and a real,
usable tool — not as a pre-built artifact smuggled into the official submission.

## If you intend to submit to NASA Space Apps 2026

Choose one, and record the decision in `docs/event/eligibility-evidence.md`:

1. **Fresh build.** Treat this repo as published prior work. During Nov 14–15, create a
   new event project and build the submission within the event window. You may rely on
   the published method/plan the same way you would rely on any public library or paper,
   subject to the official terms on original content and citations.
2. **Written clarification.** Ask the organizer whether continuing a public project is
   eligible, and keep the written answer before submitting.

## Do not, before the event, if you plan to submit

- Present this exact codebase as "created during the event."
- Remove its public history to disguise its origin.
- Claim NASA endorsement or official status.

## Always

- Cite every data source and third-party asset.
- Keep original project content under an OSI-approved license (MIT here).
- State the scope/claim firewall in the submission exactly as in the README.
